# NCPMS Photo Diagnosis

사진 판독은 1차 Gemini 외관 스크리닝, 2차 NCPMS 공식 후보 조회, 3차 Gemini 후보 비교 순서로 실행한다.

## Pipeline

1. Gemini가 사진만 보고 작물 공통 외관/상품성 이상을 분석한다.
2. 작물명 입력값을 바탕으로 NCPMS 공식 후보와 상세 도감정보를 조회한다.
3. Gemini가 사진, 1차 외관 분석, NCPMS 후보 목록을 함께 비교해 후보 목록 안에서만 최종 의심 후보를 고른다.
4. 3차 비교가 후보를 비웠고 1차 외관이 `abnormal`이면 Gemini가 사진상 양상과 NCPMS 상세정보의 의미적 유사성을 다시 비교해 공식 후보 중 하나를 고를 수 있다.
5. Gemini 재판단도 후보를 비우면 앱이 외관 라벨/근거와 NCPMS 후보명·상세 증상 텍스트를 결정론적으로 대조한다. 부패, 곰팡이, 변색, 병반, 시듦, 상처, 해충 피해 같은 범용 외관 근거가 NCPMS 공식 후보 텍스트와 기준 이상 겹치는 경우에만 낮은 신뢰도의 우선 확인 후보를 제시한다.

## Roles

- Gemini 1차: 업로드 사진에서 부패, 곰팡이, 변색, 상처, 시듦/마름, 해충 피해 흔적, 촬영 품질 제한 같은 작물 공통 외관 이상을 먼저 정리한다.
- NCPMS 2차: 작물명에 맞는 병/해충 후보, 도감 상세정보, 대표/상세 이미지, 방제/예방법 원문 섹션을 제공한다.
- Gemini 3차: 사진, 1차 외관 분석, NCPMS 후보 요약을 비교해 후보별 가능성, 요약, 현장 확인 항목을 정리한다.
- FieldGuard AI: 확정 진단, 처방, 방제 지시를 제공하지 않는다.
- NCPMS API는 업로드 사진을 직접 판독하지 않는다. 사진 판독은 Gemini가 수행하고, NCPMS는 작물코드 기반 공식 후보 목록·상세 증상·공식 이미지를 제공한다.

## Crop-Agnostic Appearance Screening

- `appearanceAssessment`는 NCPMS 후보 ID 제한을 받지 않는다.
- 작물 종류와 무관한 외관/상품성 이상만 범용 라벨로 표시한다.
- 허용 방향은 `부패 의심`, `곰팡이 의심`, `변색`, `상처/터짐`, `시듦/마름`, `해충 피해 흔적`, `촬영 품질 제한` 같은 관찰 라벨이다.
- 병명, 해충명, 처방명은 이 영역에서 만들지 않는다.
- NCPMS 후보가 0개여도 Gemini 외관 스크리닝은 실행한다.

## Candidate References

- `getNpmsPhotoDiagnosisReferences(cropName, limit)`가 작물명 기준 사진 판독 후보를 만든다.
- `SVC13` 작물 소분류별 이미지 검색 결과를 우선 사용한다.
- `SVC13` 후보가 부족하면 `SVC16` 통합검색의 병(`NP01`)과 해충(`NP03`) 후보로 채운다.
- 사진 판독 실행 시 NCPMS 후보 조회 범위는 16개까지 넓혀 후보 누락에 따른 흔들림을 줄인다.
- Gemini 비교 전에 1차 외관 라벨/근거와 후보명·상세 증상 텍스트가 많이 겹치는 후보를 앞쪽으로 정렬한다.
- 같은 상세키를 가진 후보는 `cropCode:detailServiceCode:detailKey` 기준으로 중복 제거한다.
- 상세키가 있으면 `SVC05` 또는 `SVC07`로 증상, 피해, 생태 같은 도감 섹션을 붙인다.
- 상세 응답의 `imageList`, `virusImgList`, `spcsPhotoData` 이미지는 후보 참조의 `images`로 보존한다.
- 상세 조회 실패는 해당 후보의 `sections`와 `images`만 비우고 후보 자체는 유지한다.

## Gemini Constraint

Gemini 프롬프트는 다음 규칙을 포함한다.

- 제공된 NCPMS 후보 ID 안에서만 선택한다.
- 목록 밖 병명이나 해충명은 만들지 않는다.
- `candidateId`는 반드시 후보 목록의 ID 중 하나여야 한다.
- `name`은 NCPMS 후보명을 그대로 사용한다.
- 사진에서 NCPMS 후보와 연결되는 병징, 변색, 벌레, 피해 흔적이 확인되지 않으면 후보를 억지로 고르지 않고 `candidates: []` JSON을 반환한다.
- NCPMS 후보 없음 결과는 “판매 가능” 확정 판정이 아니다. 크기, 상처, 부패, 당도, 잔류농약, 선별 기준은 별도 확인 항목으로 안내한다.

응답 schema는 다음 필드를 사용한다.

```json
{
  "appearanceAssessment": {
    "status": "normal|abnormal|uncertain",
    "confidence": "low|medium|high",
    "labels": ["부패 의심"],
    "summary": "작물 공통 외관 이상 요약",
    "reasons": ["사진에서 보이는 외관 근거"],
    "actions": ["현장 확인 항목"]
  },
  "candidates": [
    {
      "candidateId": "VC010803:SVC05:D00004102",
      "name": "궤양병",
      "confidence": "low|medium|high",
      "summary": "사진 병징과 NCPMS 도감정보 비교 요약",
      "reasons": ["판단 근거"],
      "checks": ["현장 확인 항목"]
    }
  ],
  "limitations": [""],
  "photos": [""],
  "checklist": [""]
}
```

파서는 NCPMS 후보 ID 목록 밖의 후보를 제거한다. 유효한 `candidateId`와 다른 `name`이 오면 NCPMS 원본 후보명으로 덮어쓴다.

## Limited Results

다음 조건에서는 병해충 후보를 확정하지 않는다.

- NCPMS 후보가 0개인 경우
- NCPMS 후보 조회가 실패한 경우
- Gemini가 NCPMS 후보 목록 밖의 후보만 반환한 경우
- 사진에서 병징 또는 해충 피해 근거가 보이지 않는 경우
- Gemini 응답이 최종 재시도 후에도 JSON으로 구조화되지 않는 경우

제한 결과는 후보명을 만들지 않고, 작물명 확인과 병반, 변색, 상처, 벌레, 피해 부위 재촬영 안내를 표시한다. 단, NCPMS 후보가 0개인 경우에도 외관 스크리닝은 가능한 범위에서 수행한다.
사진상 NCPMS 후보와 연결되는 병징/해충 피해가 보이지 않는 경우는 빨간 오류 패널 대신 “NCPMS 후보 없음” 상태로 표시하되, 판매 가능 여부는 사진 판독만으로 확정하지 않는다는 문구를 함께 둔다.

## UI Rules

## PSIS 등록농약 후보 표시

- 사진 판독 후보 카드의 농약 영역은 PSIS 등록정보를 먼저 50건까지 조회한 뒤 대표 후보 3개로 줄여 표시한다.
- 대표 후보는 같은 성분/사용기준의 상표 중복을 묶은 결과이며, 후보가 많을 때는 Gemini가 공식 등록정보 안에서 3개를 선택한다.
- 표시 문구는 초보 농업인이 읽을 수 있도록 `먼저 확인할 이유`, `사용 기준`, `안전 기준`, `상표 후보`로 구성한다.
- 작용기작 원문 코드와 복잡한 전문 용어는 카드 전면에 노출하지 않는다.
- 이 영역은 확정 진단, 자동 처방, 농약 우선순위 추천이 아니라 공식 등록정보 확인 보조 기능이다.

- 결과는 외관 스크리닝 패널과 Top 3 NCPMS 후보 카드로 분리해 표시한다.
- 외관상 이상이 있으면 `외관상 이상 소견`을 먼저 표시한다.
- NCPMS 후보가 연결되지 않은 경우 문구는 `NCPMS 병해충 후보와 명확히 연결되지 않음`으로 표시한다.
- 단, 1차 외관이 `abnormal`이고 Gemini 후보 선택이 계속 비어 있어도 외관 근거와 NCPMS 상세 증상 텍스트가 명확히 겹치면 `낮음` 신뢰도의 공식 후보를 표시한다.
- 기본 노출은 순위, 후보명, 가능성 배지, 한 줄 요약, NCPMS 공식 이미지 갤러리, 확인 항목 1개로 구성한다. 공식 이미지는 잘림 없이 전체가 보이도록 표시하고, 넓은 화면에서는 2열 반응형 배치로 표시한다.
- 후보 카드의 대표 공식 이미지는 NCPMS 응답 순서를 그대로 쓰지 않고, 촬영 부위와 판독 근거에 맞춰 연관도 높은 이미지를 먼저 고른다. 이미지 제목/분류의 `열매/과실`, `잎`, `줄기/가지`, `뿌리`, `꽃` 같은 범용 부위 신호와 `증상`, `병징`, `부패`, `곰팡이`, `변색`, `반점`, `해충 피해` 같은 증상 신호를 판독 문맥과 대조한다.
- NCPMS 상세 섹션 중 방제/예방 관련 원문은 `NCPMS 제공 작업`으로 별도 표시하되, 확정 처방이 아니라 공식 원문 참고와 안전사용지침 확인 대상으로 제한한다.
- 판단 근거 여러 줄, 추가 확인, NCPMS 상세정보는 `NCPMS 근거 보기` 접힘 영역에 둔다.
- 각 후보 카드에는 PSIS 공식 등록농약 후보 요약을 함께 표시한다.
- 등록농약 요약은 공식 등록정보 확인용이며, 확정 진단/자동 처방/우선순위 추천으로 표현하지 않는다.
- “농사로 공식 자료 비교” 패널은 사용하지 않는다.

## 2026-05-11 Evidence Fallback 복구

- 3차 Gemini 비교와 AI 재판단이 모두 `candidates: []`를 반환해도 1차 외관 분석이 `abnormal`이면 결정론적 evidence fallback을 한 번 적용한다.
- fallback은 외관 라벨/요약/근거와 NCPMS 후보 상세 증상 텍스트를 `부패/썩음`, `곰팡이`, `병반/무늬`, `변색`, `시듦/마름`, `상처/터짐`, `해충 피해` 그룹으로 점수화한다.
- 점수가 내부 기준 이상인 NCPMS 공식 후보만 `낮음` 신뢰도로 최대 3개 표시한다. 기준 미달이면 후보를 만들지 않고 기존처럼 `NCPMS 병해충 후보와 명확히 연결되지 않음`으로 남긴다.

- 사진 판독 완료 시 `diagnosis_records`에 별도 기록을 자동 저장한다.
- 현장 체크리스트 버튼은 새 기록을 만들지 않고 자동 저장된 기록의 `checklist`만 업데이트한다.
- 저장 기록은 `expires_at = 저장 시점 + 30일`로 보관기간을 가진다. 만료 기록은 조회에서 제외하고 Supabase 정리 작업으로 삭제한다.
- 저장 기록에는 판독 이미지 data URL, 원본 파일명, 판독 당시 필지 스냅샷, 전체 `DiagnosisResult` JSON, 최초 표시용 NCPMS 후보 참고 데이터를 포함한다. 큰 이미지는 720px 기준 JPEG preview로 축소해 저장한다.
- `/diagnosis`의 `저장된 사진 판독 기록` 섹션에서 최근 30일 기록을 다시 확인할 수 있다.
- 저장된 사진 판독 기록 항목을 클릭하면 저장된 `DiagnosisResult`와 NCPMS 후보 참고 데이터를 기반으로 최초 판독 완료 직후의 `사진 판독 결과` 카드와 같은 구성을 인라인으로 펼친다.
- 저장된 사진 판독 기록은 각 항목의 휴지통 버튼으로 삭제할 수 있다. 삭제 시 해당 `diagnosis_records.id` row만 제거하고 목록을 다시 조회한다.
