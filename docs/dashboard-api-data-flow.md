# Dashboard API Data Flow

## NCPMS 상세보기 반영

- 대시보드의 `NCPMS 작물별 후보` 영역은 `SVC16` 통합검색 결과를 별도로 조회해 병/해충 후보 카드로 표시한다.
- 대시보드 후보는 NCPMS `totalCount`, `startPoint`, `displayCount` 메타데이터를 기준으로 가능한 전체 페이지를 수집한 뒤 6개 단위 페이지네이션으로 표시한다.
- 후보 카드에는 NCPMS `thumbImg`, 병/해충 구분, 한글명, 학명/작물명이 표시된다.
- `자세히보기` 버튼은 후보의 `detailServiceCode`와 `detailKey`를 사용한다.
  - `SVC05`: 병 상세정보 서비스, `sickKey`로 조회
  - `SVC07`: 해충 상세정보 서비스, `insectKey`로 조회
- 상세 패널은 NCPMS 상세 응답의 본문 HTML `<br/>`을 줄바꿈 텍스트로 정리하고, `imageList`, `virusImgList`, `spcsPhotoData` 이미지를 공식 이미지로 표시한다.
- 이 정보는 실제 필지 발생 확정 자료가 아니라, 선택 작물에 대해 NCPMS에 등록된 공식 병해충 후보와 확인 자료를 보여주는 기능이다.

## 검토 기준

대시보드 화면은 선택 필지 1개를 기준으로 현재 날씨, 병해충 확인 권고, 공식 자료 근거, 작업 카드, 타임라인을 보여준다. 이 문서는 현재 코드 기준으로 실제 연결된 API와 화면 영역의 매칭을 정리한다.

## 외부 API 상세

### 기상청_단기예보 조회서비스

- 사용 API:
  - `초단기실황조회`
  - `단기예보조회`
- 코드 호출명:
  - `ultraSrtNcst`
  - `vilageFcst`
- 처리 방식:
  - 필지 위경도를 기상청 DFS 격자 `nx`, `ny`로 변환한다.
  - 초단기실황과 단기예보를 함께 조회한다.
  - 초단기실황 값을 우선 사용하고, 없는 값은 단기예보 값으로 보완한다.
  - 강수, 기온, 풍속, 습도를 `assessWeatherRisk()`로 점수화한다.

### 국가농작물병해충관리시스템(NCPMS) OpenAPI

- 사용 API:
  - `SVC16` 통합검색 서비스
  - `SVC05` 병 상세정보 서비스
  - `SVC07` 해충 상세정보 서비스
  - `SVC13` 작물 소분류별 이미지 검색 서비스
- 처리 방식:
  - 앱 작물명을 NCPMS 작물코드로 변환한다. 로컬 매핑은 빠른 조회와 별칭 보정에 사용하고, 로컬 매핑에 없으면 `SVC16`에 `cropName`, 이후 `searchName`으로 조회해 NCPMS 응답의 `cropCode`를 동적으로 찾는다.
  - `논`, `벼`는 `논벼` / `FC010101`로 변환한다.
  - `토마토`는 `VC010803`으로 변환한다.
  - `수박`, `수박밭`은 `수박` / `VC010801`로 변환한다.
  - `깻잎`, `들깻잎`은 NCPMS 공식 작물명 `들깨` / `IC011602`로 변환한다.
  - `복숭아`, `복숭아밭`은 `복숭아` / `FT020604`로 변환한다.
  - 대시보드 후보는 `SVC16`에 `cropCode`와 `divCode=NP01`(병), `divCode=NP03`(해충)을 넣어 조회한다.
  - 대시보드 후보는 `startPoint`를 증가시키며 가능한 전체 페이지를 수집하고, 중복 제거 후 화면에서 6개씩 페이지네이션한다.
  - `detailUrl`에 포함된 API 키는 화면과 저장 문자열에 노출하지 않고 상세키만 추출한다.
  - 사진 판독 후보는 `SVC13` 작물별 이미지 후보를 우선 사용하고, 부족하면 `SVC16` 병/해충 후보로 보완한다.
  - Gemini 사진 판독은 NCPMS 후보 ID 목록 밖의 병명이나 해충명을 만들 수 없다.
  - NCPMS 후보는 작물별 공식 카탈로그 자료이므로 후보 개수만으로 위험 점수를 올리지 않는다.

### 농사로 Open API - 농작물재해예방정보

- 사용 API:
  - `frcDsstrPrevntYear`
  - `frcDsstrPrevntLst`
- 처리 방식:
  - 현재 기상 조건이 고온, 저온, 강수, 강풍 기준을 만족할 때만 조회 키워드를 만든다.
  - 조회 조건이 없으면 대시보드에는 `현재 기상 조건에서는 농작물재해예방정보 조회 조건 없음`을 표시한다.
  - 조회 조건이 있으면 관련 재해예방자료를 병해충 확인 권고의 보조 공식 근거로 합친다.

## 현재 UI 판단

기존 화면은 종합 위험도 점수가 기상 점수인지 병해충 확인 권고 점수인지 구분하기 어려웠다. 현재 구현은 다음 방식으로 개선했다.

- `오늘 위험도`에 종합 점수와 기준 출처를 함께 표시한다.
- `오늘 위험도`와 NCPMS 후보 영역에 필지 등록 시 사용자가 입력한 `crop_name`을 선택 작물 기준값으로 표시한다.
- `기상 위험`과 `병해충 확인 권고`를 별도 카드로 분리해 각각의 점수, 등급, API 명칭을 표시한다.
- 병해충 영역은 NCPMS 작물별 후보와 상세정보만 병해충 근거로 표시한다.
- 농작물재해예방정보는 실제 조회 조건이 있는지 별도 상태로 표시한다.
- 동일 필지, 동일 후보명, 동일 점수의 병해충 예보는 30분 안에 재저장하지 않아 타임라인 반복 노이즈를 줄인다.

## 사용자에게 전달되는 기능 의미

- `오늘 위험도`: 지금 어떤 이유로 더 주의해야 하는지 빠르게 보는 우선순위 지표다.
- `날씨 위험`: 실제 기상 조건이 농작물 피해나 병해충 취약성을 높이는지 확인하는 영역이다.
- `NCPMS 작물별 병해충 확인 권고`: NCPMS 작물별 병/해충 후보와 현재 날씨를 근거로 현장 확인 필요성을 알려주는 영역이다.
- `농작물재해예방정보`: 기상 조건이 재해예방자료 조회 대상인지 알려주는 보조 근거 영역이다.
- `타임라인`: 수집, 권고, 작업 기록이 반복적으로 쌓이는 이력 영역이다.

## 남은 개선점

- 작업 카드가 위험 원인과 자동으로 연결되는지 화면에서 명확히 보이지 않는다.
- 필지 지도는 현재 미리보기 상태라, 선택 필지 위치와 위험 상태를 지도 위에서 확인할 수 없다.
 
## 사진 판독 NCPMS 후보 매칭

- 사진 판독은 1차 Gemini 외관 분석에서 작물 공통 이상 징후를 먼저 추출한다.
- NCPMS는 이미지를 직접 판독하지 않고, 작물코드 기반 공식 후보 목록과 상세 증상 정보를 제공한다.
- NCPMS 후보 목록은 촬영 부위 입력값과 1차 외관 분석에서 추론한 식물 부위를 기준으로 한 번 더 제한한다. 예를 들어 열매 사진에서는 과실·과면·과피·송이 등과 연결되는 후보를 우선하고, 잎·가지·줄기 전용 후보는 3차 비교 프롬프트와 화면 참조 목록에서 제외한다. 상세 증상에 여러 부위가 섞인 후보도 촬영 부위 표현보다 다른 부위 표현이 더 우세하면 제외한다.
- 3차 Gemini 비교 단계에는 사진, 1차 외관 분석, NCPMS 후보 목록과 상세 증상 정보를 함께 전달한다.
- 3차 비교 결과가 후보를 비웠고 1차 외관 상태가 `abnormal`이면, 별도 Gemini 재판단 단계가 사진상 양상과 NCPMS 상세 증상의 의미적 유사성을 비교해 공식 후보 중 하나를 선택할 수 있다.
- 이 재판단은 키워드 점수나 단순 문자열 포함 여부로 결정하지 않는다. 후보를 고를 때도 반드시 NCPMS 후보 목록 안의 `candidateId`와 이름만 사용한다.
- Gemini 재판단도 후보를 비우면 앱 내부 fallback이 외관 라벨/근거와 NCPMS 후보명·상세 증상 텍스트를 대조한다. 기준 이상 겹치는 공식 후보가 있을 때만 `낮음` 신뢰도로 표시하고, 목록 밖 후보는 만들지 않는다.
- 사진 판독 후보 카드에는 NCPMS 상세 이미지와 방제/예방 관련 원문 섹션을 각각 `NCPMS 공식 이미지`, `NCPMS 제공 작업`으로 표시한다.
- 결과는 확정 진단이 아니라 현장 확인이 필요한 공식 후보 추천이다.
