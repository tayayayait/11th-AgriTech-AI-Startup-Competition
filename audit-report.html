🔴 1. Eliminating Waterfalls CRITICAL · 통과
규칙판정근거
1.1 Defer Await Until Needed 통과 서비스 레이어에서 불필요한 선행 await 없음. 조건 분기 후 fetch 호출 패턴 준수.
1.2 Dependency-Based Parallelization 통과 종속 관계가 있는 호출에서 Promise 체이닝 활용 확인. consultationService.ts:506
1.3 Prevent Waterfall Chains in API Routes N/A Vite SPA — 서버 API 라우트 없음 (Supabase Edge Function은 별도 저장소)
1.4 Promise.all() for Independent Operations 통과 19개 파일에서 Promise.all / Promise.allSettled 적극 사용 확인. weatherLiveService.ts:121 npmsPestService.ts:298
1.5 Strategic Suspense Boundaries 권고 React.lazy / Suspense 미사용. 모든 페이지를 정적 import로 번들링. 코드 스플리팅 부재.
→ Dashboard, Tasks(52KB), Diagnosis(46KB) 등 대형 컴포넌트에 lazy 적용 권장
🔴 2. Bundle Size Optimization CRITICAL · 부분 통과
규칙판정근거
2.1 Avoid Barrel File Imports 권고 lucide-react 배럴 임포트 전수 사용 (Dashboard.tsx에서 14개 아이콘 한 줄 임포트). Radix UI도 배럴 패턴.
→ lucide-react/dist/esm/icons/ 직접 임포트 또는 vite.config.ts에 optimizePackageImports 추가
2.2 Conditional Module Loading 통과 팜맵 SDK를 loadFarmmapSdk()로 동적 로드. farmmapSdk.ts
2.3 Defer Non-Critical Libraries 통과 sonner(토스트), recharts 등은 사용 시점에서만 렌더링.
2.4 Dynamic Imports for Heavy Components 미통과 React.lazy 사용 없음. App.tsx에서 8개 페이지 전부 정적 import.
→ Diagnosis(46KB), FieldNew(53KB), Tasks(52KB) 등 lazy import 필수
2.5 Preload Based on User Intent N/A lazy import 미사용이므로 preload 패턴 불필요. lazy 도입 후 적용 가능.
🟠 3. Server-Side Performance N/A — Vite SPA
규칙판정근거
3.1–3.7 (전체) N/A Next.js RSC/Server Actions 전용 규칙. Vite SPA 프로젝트에는 해당 없음. Supabase Edge Function 보안은 별도 검토 필요.
🟡 4. Client-Side Data Fetching MEDIUM-HIGH · 통과
규칙판정근거
4.1 Deduplicate Global Event Listeners 통과 전역 이벤트 리스너 최소 사용. sidebar의 keydown만 단일 등록. sidebar.tsx:87
4.2 Passive Event Listeners 권고 FarmmapView의 resize 리스너에 { passive: true } 미적용.
→ FarmmapView.tsx:337 resize 이벤트에 passive 옵션 추가 권장
4.3 Use SWR / TanStack Query 통과 @tanstack/react-query 전면 도입. queryKey 기반 자동 중복제거·캐싱·staleTime 설정 완료.
4.4 Version and Minimize localStorage 권고 localStorage 키에 버전 프리픽스 없음. try-catch 일부만 적용.
→ client.ts:19 getOrCreateOwnerId()에 try-catch 없음 (Safari 비공개 모드 에러 가능)
🟡 5. Re-render Optimization MEDIUM · 양호
규칙판정근거
5.1 Defer State Reads 통과 useSearchParams 미사용. URL 상태 읽기가 콜백 내부에서만 수행됨.
5.2 Don't wrap simple primitives in useMemo 통과 단순 boolean 표현식을 useMemo로 감싸지 않음 (canGenerateTasks 등 직접 계산).
5.4 Extract to Memoized Components 권고 Dashboard.tsx(719줄), Tasks.tsx(1222줄) — 단일 컴포넌트가 과도하게 큼. 하위 섹션을 memo 컴포넌트로 추출 권장.
5.5 Narrow Effect Dependencies 통과 useEffect 의존성에서 selected?.id, selected?.crop_name 등 원시값 사용 확인.
5.6 Subscribe to Derived State 통과 useIsMobile() 훅이 matchMedia + boolean 상태만 구독. use-mobile.tsx
5.7 Functional setState Updates 통과 페이지네이션에서 setPage(p => Math.max(1, p-1)) 패턴 확인. Dashboard.tsx:479
5.8 Lazy State Initialization 통과 useState(() => readStoredSelectedId()) 함수형 초기화 사용. SelectedFieldContext.tsx:52
5.9 Transitions for Non-Urgent Updates N/A 연속 스크롤/입력 기반 상태 업데이트 없음. 현재 구조에서 불필요.
🟡 6. Rendering Performance MEDIUM · 양호
규칙판정근거
6.2 CSS content-visibility 권고 Tasks.tsx의 농작업일정 목록(다수 카드), Dashboard의 NCPMS 후보 목록에 content-visibility: auto 적용 시 렌더링 개선 기대.
6.3 Hoist Static JSX 통과 workflowSteps, featureCards 등 정적 데이터를 컴포넌트 외부 상수로 추출. Home.tsx:81-112
6.7 Explicit Conditional Rendering 통과 !!selected, length > 0 등 명시적 조건 사용. falsy 렌더링 위험 없음.
🟢 7. JavaScript Performance LOW-MEDIUM · 양호
규칙판정근거
7.2 Build Index Maps 통과 groupScheduleEras()에서 Map 기반 그룹 인덱싱. Tasks.tsx:148
7.8 Early Return 통과 Guard 패턴 전반적 적용. if (!selected) return 등 초기 반환 일관 사용.
7.11 Set/Map for O(1) Lookups 통과 Map 사용 확인 (groupIndexes). 대량 데이터 탐색에 효율적 자료구조 활용.
🟢 8. Advanced Patterns LOW · 해당 없음
규칙판정근거
8.1–8.2 Ref-based Handlers N/A useCallback 패턴으로 충분히 안정적 콜백 관리 중. 고급 패턴 적용 불필요.
🟠 아키텍처 부가 분석
항목판정근거
Context Provider 메모이제이션 통과 AuthContext, SelectedFieldContext 모두 useMemo로 value 객체 안정화. useCallback으로 함수 안정화 완료.
QueryClient 구성 권고 new QueryClient()에 defaultOptions 미설정. staleTime, gcTime 전역 기본값 권장.
→ 각 useQuery마다 개별 staleTime 설정 중 — 전역 기본값으로 중복 제거 가능
컴포넌트 크기 미통과 Tasks.tsx(1222줄), FieldNew.tsx(1300+줄), Diagnosis.tsx(1100+줄) — 단일 파일 800줄 초과. 유지보수성 저하.
→ 섹션별 하위 컴포넌트 추출 + memo() 적용 필수
Vite 빌드 최적화 통과 resolve.dedupe로 React 중복 방지. SWC 플러그인 사용으로 빌드 속도 최적화.

📋 핵심 개선 권고 요약 (우선순위순)

  1. 1React.lazy + Suspense 도입 — App.tsx에서 8개 페이지를 lazy import로 전환. 초기 번들 40-60% 감소 기대. CRITICAL
  2. 2lucide-react 직접 임포트 — 배럴 임포트를 개별 아이콘 경로로 변경. 콜드 스타트 200-800ms 절감. CRITICAL
  3. 3대형 컴포넌트 분할 — Tasks.tsx, FieldNew.tsx, Diagnosis.tsx를 300줄 이하 하위 컴포넌트로 추출 + memo(). HIGH
  4. 4localStorage try-catch 일관 적용 — client.ts의 getOrCreateOwnerId()에 try-catch 추가. Safari 비공개 모드 크래시 방지. MEDIUM
  5. 5QueryClient 전역 기본값 — defaultOptions.queries에 staleTime, gcTime 설정. 개별 설정 중복 제거. MEDIUM
  6. 6content-visibility 적용 — 긴 목록 렌더링 성능 개선. Tasks 농작업일정, Dashboard NCPMS 후보 대상. LOW
  7. 7resize 이벤트 passive 옵션 — FarmmapView.tsx의 window.addEventListener에 { passive: true } 추가. LOW
